## Design Specificity Verdict

**The design system is authored for this product. The interface is not.**

PRODUCT.md names five facts about the real content: four cards are the same tool at different models; two are the same service under different identities; a third of URLs resolve only on this machine; the name field carries hand-typed metadata (`(C/O - Jan25)`); 16 of 20 open as a tab, 4 as a popup.

The interface responds to zero of them. All 20 cards get identical treatment. Nothing marks a local-only URL, nothing groups the ollama variants, nothing makes `u/0` vs `u/1` legible. Swap Mark's 20 entries for any stranger's 20 bookmarks and not one pixel would look wrong. That is the definition of unauthored.

**Deterministic scan.** CLI detector: exit 2, 4 findings — `side-tab` (line 108), `design-system-font-size` ×3 (lines 178, 259, 669). Browser detector (injected at localhost:8400): 6 findings — 2× `low-contrast` on the empty-state text, `gpt-thin-border-wide-shadow` on `div.modal`, plus three false positives.

**Detector caught what both reviewers missed:** `gpt-thin-border-wide-shadow` on `.modal` — 1px border plus 24px shadow blur is the generic-AI-output signature, and DESIGN.md sanctions it as the "Float" token.

**False positives:** `dark-glow #d97757` (the Chrome extension's own overlay — `grep -c d97757` = 0); `overused-font: roboto` (4th fallback, never renders on macOS); `cream-palette` (the warm paper ground is a committed, documented decision); `side-tab` (DESIGN.md explicitly specifies the 3px category flag).

## Overall Impression

This is a fast, calm, well-organized surface with a genuinely good visual system and an interaction layer that has never been built. The scores tell the story: every visual heuristic sits at 2, every interaction heuristic at 1. The single biggest opportunity is that one change — making the card an `<a>` instead of a `<div>` — fixes keyboard access, screen-reader semantics, status-bar URL preview, context menus, and ⌘-click simultaneously, at zero visual cost.

## What's Working

**The performance architecture is the UX.** System fonts, no build, no dependencies, no network on load. For a surface that exists to be abandoned in two seconds, time-to-interactive *is* the experience, and this wins outright against every hosted start page.

**Category deletion reassigns instead of orphaning, and says so.** It computes the affected count, resolves a destination, and names both in the confirm. The best copy in the file, at the moment care is most expensive.

**The visual system refuses its two obvious neighbors.** Warm paper instead of cool grey is load-bearing, not taste. The system is disciplined enough that its violations are diagnosable.

## Priority Issues

### [P0] Cards are `<div>`s — the primary action has no keyboard path and no browser semantics
`index.html:680`. Measured: 0 of 10 cards tabbable, `tabIndex` = -1, no `role`, no `aria-*`. 18 Tab presses produced 17 stops, none a card. Every launch target is invisible to keyboard and screen reader.

Beyond accessibility, this breaks the muscle memory of the exact user it is built for: ⌘-click does nothing, middle-click does nothing, right-click offers no "Copy link address", and hovering shows no status-bar URL — the one place a full URL belongs, and the one place it doesn't appear, while a break-all copy eats 60% of the card.

**Fix:** render as `<a href="${app.url}" target="_blank" rel="noopener noreferrer">`. Intercept click only for `type === 'popup'`, and bail when `e.metaKey || e.ctrlKey || e.shiftKey || e.button === 1`.

### [P0] Popup mode opens a duplicate window on every click
`index.html:706-711`. `noopener=yes` inside the features string nullifies the `win_${app.id}` target name, so window reuse never happens. Verified in-browser: with `noopener`, two calls to the same name returned `null` and produced two windows; without it, the same calls returned an identical handle.

This hits the 5 popup entries — the Local LLM chats and the Passkey Tracker, i.e. the first-party tools PRODUCT.md says are increasingly the point.

**Fix:** drop `noopener=yes,noreferrer=yes` from the features string. Keep the named target, and hold returned handles in a `Map` keyed by `app.id` so a re-click can `.focus()` a window that drifted behind.

### [P1] Import can destroy the only copy of the configuration behind one native confirm
`index.html:874-906`. Export/Import is the entire sync and backup story, so this runs at every device switch — and its safety net is one unstyled `confirm()` naming neither the file nor its contents nor what is lost. No snapshot of prior state.

**Fix:** (a) write current state to `dashboardBackupPrev` before overwriting, and surface a "Restore previous" control when that key exists; (b) replace the confirm with the styled modal showing a real comparison ("12 apps in 3 categories → you currently have 20 in 4"); (c) date-stamp the export filename.

### [P1] The card spends its space on the two fields carrying the least information
On 11 of 20 cards the URL block occupies more ink than the name. The Cloudflare card renders 4 lines of hex. The mode chip — the most saturated element — reads "Tab" on 16 of 20, violating DESIGN.md's own One Signal Rule (blue means *responds to you*; the chip is read-only).

Meanwhile there is no recognition signal at all: no favicon, no monogram. A launcher scanned a hundred times is the strongest case for iconography in all of UI.

**Fix:** cut the URL to origin, or drop it once the card is an `<a>` and show the discriminating segment only on name collision; add a 32px monogram tile; mark only the 4 popup cards and drop the chip from the other 16.

### [P2] Disclosure logic is backwards, and the hover state damages the card title
Category Rename/Delete render permanently — 8 always-on controls, one destructive, for a yearly action. Card ✎/× are `display:none` until `:hover` with no `:focus-within`, so editing and deleting an app are keyboard-impossible. Both are under the WCAG 2.5.8 24×24 minimum and sit 4px apart.

Verified defect: the `.card-actions` strip is 48×24px with an opaque white background at `top:5px; right:5px`, and it overlaps the title whenever the title wraps to two lines — on "Gemini 3.5 Flash (C/O - Jan25)" it punches a white hole through "Flash". The hover state damages the element DESIGN.md calls "the only thing a user actually reads."

**Fix:** move all editing behind one header "Edit" toggle. At rest show only destinations; in edit mode show properly-sized persistent controls. Removes 8 controls from the scan, gives editing a keyboard path, and eliminates the overlap.

## Minor Observations

- **`card.innerHTML` interpolates `${app.name}` and `${cleanUrl}` unescaped** (line 690). Since import is the sync path, a tampered JSON file executes script on load. Use `textContent` for the name.
- **The product has four names**: "MSK-Dashboard" (title/h1), "App Control Center" (manifest), `control_center_config.json` (export), "launchpad" (import confirm).
- **Export filename is undated**, so the Downloads folder fills with `(1)`, `(2)`, `(3)` for a file that is both the sync mechanism and the only backup.
- **Nothing marks the third of entries that only resolve on this machine** — `.card-url` strips only the protocol, so `localhost:8080/…` and `app.netlify.com/…` render at identical weight.
- **At 400px the header doesn't wrap** — both `header` and `.header-actions` are `flex-wrap: nowrap`, so `+ Add App` squashes to 55×67px across 3 lines and overflows the content box by 79px. The file contains zero `@media` queries.
- **`getCategoryDragAfterElement` (line 514)** finds the last section whose center is above the cursor, not the nearest below as its comment claims. Behavior right, comment wrong.
- **DESIGN.md has two errors of my own**: its machine-readable `typography` block omits the `0.7rem` chip step its prose documents (which is what the detector flagged at line 178), and it names the chip values "POPUP / TAB" when the code renders "Utility / Tab".

## Questions to Consider

1. **If the URL exists only to disambiguate two Gmails and four ollama models, why is it on all twenty cards?** Show it only where names collide, and only the segment that differs — recovering 60% of every card's area for the thing that actually gets scanned.
2. **The chip reads "Tab" on 16 of 20 cards. What is a signal that's right 80% of the time actually telling you?**
3. **Twenty items fit in one viewport. So what's the fastest path — the eye finding a card, or a keystroke?** `⌘K → "qwe" → Enter` beats scan-and-aim past about a dozen items, and would resolve most of the P0 keyboard failure as a side effect.
4. **If the export file is the save file, why is there exactly one slot and no history?** What would change about how freely you rearrange things if every import were reversible?
